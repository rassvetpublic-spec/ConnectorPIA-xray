# Auto Project Initialize

При начале нового рабочего контекста агент действует автоматически и без лишних вопросов.

## Обязательное чтение

1. `README.md`
2. `AGENTS.md`
3. применимые `.agent/rules/*.md`
4. открытый Issue/PR текущей задачи
5. текущее состояние branch/HEAD

## Проверка структуры

Минимально должны существовать:
- `README.md`
- `AGENTS.md`
- `.gitignore`
- `.agent/rules/issue_driven_workflow.md`
- `.agent/rules/safe_sync_gate.md`
- `.agent/rules/security.md`
- `.github/PULL_REQUEST_TEMPLATE.md`
- `.github/workflows/ci.yml`

Если обязательный файл пропал — не создавать параллельный аналог. Оформить/использовать Issue и восстановить канонический путь.

## Issue-first

Если новая задача меняет код, конфигурацию, архитектуру, правила или канонические данные репозитория, работа начинается с GitHub Issue.

Нельзя создавать незатреканные «быстрые» исправления в `main`.

## Локальный workspace

Локальные `outputs`, временные файлы, traces, browser/IDE state и прочий runtime material можно читать и анализировать, но нельзя автоматически добавлять в Git.

Для переноса в репозиторий нужен отдельный inventory/sanitization step и Issue-контракт.

## Память и история

История решений хранится в GitHub Issues/PR и канонической документации репозитория. Не создавать автоматически `newmemory/`, скрытые журналы решений или вторую базу истины внутри репозитория.
