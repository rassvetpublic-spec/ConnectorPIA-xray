# Happ + PIA: запуск и контроль

Запуск: **Happ + PIA.lnk**. Подключает Happ, затем PIA и запускает скрытый монитор.
Повторное нажатие не создаёт второй монитор. Выбирается текущий сервер Happ.

Состояние: **Monitor status.lnk** или **monitor-status.html**. Страница обновляется каждые 3 секунды. Проверяйте время последней записи: закрытая программа не обновляет страницу.

Остановка контроля: **Stop monitor.lnk**. Соединения Happ и PIA остаются включёнными. Остановка может занять несколько секунд, пока закончится текущая проверка. Для возобновления снова запустите основной ярлык.

## Проверки

| Интервал | Проверка | Что означает |
|---|---|---|
| 3 с | TCP/443: ChatGPT, Gemini, Wikipedia | Удалённый адрес принимает TCP-соединение через интерфейс PIA. Это не ICMP и не проверка авторизованного чата. |
| 3 с | Текущий OpenVPN-сервер PIA через Happ, порт из pia.ovpn (сейчас 853) | На отдельном соединении отправляется один начальный пакет OpenVPN, проверяется ответ с идентификатором этой попытки. Действующее соединение PIA не затрагивается; логин и пароль не передаются. Это время подключения и ответа службы, не чистый сетевой RTT. |
| 10 с | Curl GET: chatgpt.com и gemini.google.com/app | Различает доступную страницу, явный запрет страны, CAPTCHA, неопределённый 403, 429 и сетевую ошибку. |
| 10 с | Выходной IP через 2ip.io | Показывает фактический IP проверочного запроса через PIA и формирует ссылку на геотест страны/города 2IP. Старый адрес 2ip.ru перенаправляет пользователей на 2ip.io. |

Проверки сайтов привязаны к текущему IPv4 адаптера PIA и игнорируют системный HTTP-прокси. При отсутствии подключённого PIA они не выполняются. DNS-разрешение использует текущие настройки Windows. Проверка серверов PIA идёт через HTTP-прокси Happ 127.0.0.1:10809; он должен оставаться включённым и доступным без авторизации. Основное соединение PIA по-прежнему использует SOCKS5 127.0.0.1:10808.

Новые проверки запускаются по расписанию без наложения одинаковых проверок. При зависании, смене соединения или восстановлении очередной запуск может быть пропущен. HTTP 429 включает паузу для сайта не менее 60 секунд. Страницы загружаются со сжатием; при наличии ETag используются условные запросы. Ответы ограничены 4 МБ. Тела ответов хранятся только во временной папке на время проверки и удаляются.

**HTTP 200 не доказывает готовность ChatGPT/Gemini в вашем аккаунте.** Без браузерной авторизации curl может получить только страницу входа или защиту от ботов. Монитор не использует ваши cookies и не отправляет сообщения в чат. Отсутствие явного запрета в HTML также не исключает запрет, возникающий позднее внутри приложения. Формулировки запретов могут меняться.

## Восстановление

1. Три последовательных явных запрета страны на одном сервисе: сравнить резервные регионы PIA через Happ и переключить PIA в самый быстрый из ответивших. Список берётся из локального кеша PIA; он может устареть. Проверяется до двух адресов региона. Приложение PIA само выбирает фактический сервер региона, поэтому замер кандидата не гарантирует такой же результат после подключения.
2. Три последовательных сетевых сбоя сразу у ChatGPT и Gemini: проверить Happ. Если его прокси и внешний TCP-узел отвечают, пробовать резервный PIA. Один недоступный сайт, CAPTCHA, общий 403, 429 и ошибка сервиса 5xx сами по себе не запускают перебор.
3. Если Happ не отвечает: штатно отключить PIA, переподключить текущий Happ и подключить PIA. Не более двух попыток Happ за текущую серию неудач.
4. Нет подходящих резервов либо исчерпаны попытки: пауза перебора 10 минут, продолжение мониторинга и сообщение в статусе о необходимости вручную выбрать другой сервер Happ. Автоматический выбор другого сервера Happ **не реализован**: для установленной версии не подтверждён штатный интерфейс выбора сервера. Файл конфигурации Happ не редактируется.

Между восстановлениями минимум 90 секунд; максимум 6 попыток за час. Низкая задержка не означает отсутствие геоблокировки: после подключения идут новые веб-проверки. Исходный регион PIA автоматически не возвращается, чтобы не создавать колебания между регионами.

Монитор не переключает приложения в прямой интернет как резервный режим. **У PIA во время настройки был выключен Kill Switch:** этот скрипт не заменяет его и не гарантирует блокировку трафика других приложений во время переподключений. Правила разделённого туннеля сохраняются. Для работы требуется существующее исключение core/xray.exe из PIA.

Команда запуска включает фоновый режим службы PIA. Это позволяет `piactl connect` работать без зависимости от скорости запуска графического окна. Первый отказ команды больше не завершает запуск сразу: состояние проверяется повторно до четырёх циклов. На время запуска и применения настроек монитор приостанавливает собственное восстановление, чтобы две операции не конфликтовали.

## Файлы и настройки

- `vpn-monitor.json` — интервалы, пороги, разрешённые резервные регионы. По умолчанию: Финляндия, Швеция, Нидерланды, Франкфурт, Франция. Доступность региона дополнительно сверяется со списком piactl. Это список кандидатов, а не обещание доступности сервисов.
- `monitor-status.json` — последний результат и PID монитора.
- `monitor-events.log` — изменения состояний и попытки восстановления; ограничение около 1,5 МБ с архивами. Каждая успешная проверка отдельно не записывается.
- `Connect-Happ-PIA.ps1`, `vpn_monitor.py`, `Stop-Monitor.ps1` — запуск, монитор и остановка.

Ярлыки можно скопировать на рабочий стол; остальные файлы оставьте в этой папке. Автозапуск при входе в Windows не добавлен.

## Проверка реализации

Проверены сценарии классификации (включая ложный запрет из JavaScript-переводов), порог ошибок, запрет прямого TCP-запроса без адреса PIA, сопоставление ответа OpenVPN, выбор региона в имитации и отсутствие изменений в режиме наблюдения. Живой ограниченный запуск подтвердил TCP-запросы с адреса адаптера PIA, ответы curl и отдельный ответ текущего OpenVPN-сервера. В живом тесте серверы не переключались: восстановление проверено имитацией команд, а не намеренным разрывом действующего подключения.

Формат начального обмена: [документация протокола OpenVPN](https://build.openvpn.net/doxygen/network_protocol.html). Доступность приложения Gemini зависит и от условий самого сервиса: [справка Google](https://support.google.com/gemini/answer/13575153?hl=en).
