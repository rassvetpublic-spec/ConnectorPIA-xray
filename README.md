# ConnectorPIA-xray

Рабочий репозиторий проекта **ConnectorPIA + Xray**.

Репозиторий организован по governance-модели `KAT9I_OS`: требования и решения отделены от состояния работы, автоматические проверки дают Evidence, а GitHub Project используется как представление, а не как второй источник истины.

## С чего начать

1. Прочитать [`AGENTS.md`](AGENTS.md) — обязательный порядок работы людей, AI-агентов и автоматизации.
2. Открыть [`docs/GITHUB_WORKFLOW.md`](docs/GITHUB_WORKFLOW.md) — практический GitHub-процесс.
3. Работать через Issues → ветка → PR → CI/Evidence → независимый QA при необходимости → `mtd` → merge.

## Где источник истины

- `docs/` — принятая документация, архитектура и спецификации;
- GitHub Issues — текущее состояние задач, Scope, зависимости и критерии готовности;
- GitHub Actions — машинное Evidence выполненных проверок;
- Pull Requests — проверяемый ChangeSet и review;
- Releases — официально выпущенные версии;
- GitHub Project — производное представление Issues/PR, а не отдельный источник требований.

## Главное правило merge

Merge в `main` выполняется только после явной команды владельца проекта `mtd`, `MTD` или `мтд`.

Зелёный CI, approved review и QA PASS сами по себе merge не разрешают.
