# Security Policy

## Не публиковать секреты

Нельзя добавлять в Issues, PR, commits, логи или репозиторий:

- пароли;
- API keys;
- OAuth/access/refresh tokens;
- cookies и session storage;
- приватные ключи и сертификаты;
- браузерные auth-профили;
- персональные данные, не требуемые для задачи.

## Если секрет уже попал в GitHub

1. Не копировать его в новые комментарии или PR.
2. Считать секрет скомпрометированным и отозвать/ротировать его у провайдера.
3. Зафиксировать факт инцидента без повторной публикации самого секрета.
4. При необходимости очистить историю отдельной контролируемой задачей.

Удаление строки из последнего commit не делает опубликованный секрет безопасным.

## Проверка изменений

Изменения, затрагивающие авторизацию, прокси, токены, browser profiles, хранение учётных данных или сетевую маршрутизацию, считаются повышенного риска и требуют явного анализа угроз и независимого QA.

## Generated/runtime данные

Локальные `outputs/`, логи, профили, кэши и runtime-артефакты не являются каноническим исходным кодом по умолчанию. Для их публикации требуется отдельное решение с проверкой на секреты и приватность.
